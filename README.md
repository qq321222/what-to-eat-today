# 今天吃什么 · 麦当劳智能点餐助手

> 麦当劳程序员节创意开发大赛参赛作品（非麦当劳官方产品）

基于**麦当劳 MCP（mcd-mcp）** 的 WorkBuddy Skill。用户面对几十个 SKU、4 种履约方式和一堆券时，本 Skill 完成「选门店 → 按人数/预算/口味出搭配 → 领券 → 券规则真实比价 → 下单 → 支付跟踪」全链路，**算出券后实付最低方案**，把点餐决策从约 5 分钟压缩到 30 秒，消灭比价与履约试错成本。

## 项目亮点

- **真实比价引擎**：以门店维度可用券（query-store-coupons）为唯一权威数据源，硬过滤（有效期/品类/门槛/履约）+ 打分公式 `score = E × R × (0.6 + 0.4T)` 预筛 3-5 个候选，再逐候选真实试算（calculate-price），全流程算价预算 ≤5 次。
- **四种履约方式全覆盖**：到店自取（beType=1）、得来速（5）、麦乐送（2）、团餐（6，含满减满折促销叠加与助餐服务）。
- **状态机式交互**：首轮不追问——收到意图立即按默认假设（1 人/人均 30-40 元/到店自取）给方案，每轮最多补一个问题；硬确认词表防止「嗯/随便」误触下单。
- **复购分支**：「再点一次上次那个」一键还原历史订单明细，按本次门店与履约重新试算后下单。
- **不虚构**：任何价格、订单状态均来自真实 MCP 调用；下单结论只复述 create-order 真实返回。
- **依赖检查与降级**：内置只读环境检查器（ready / needs_setup / partial / unavailable 四态路由），脚本失败自动降级为人工推理且声明「估算价」。

## 目标用户

- 想在麦当劳快速点单又纠结「怎么点最划算」的用户
- 多人拼餐、预算有限的学生/上班族
- 需要团餐搭配与满减凑单的企业订餐人
- 开车路过想用得来速不停车取餐的用户

## 安装方法

前置条件：WorkBuddy 客户端 + 已安装并授权麦当劳 MCP 连接器（对话左下角「+」连接器菜单 → 搜索「麦当劳」→ 安装并完成账号授权）。

1. 下载本仓库（或 Release 中的 `what-to-eat-today.zip`）。
2. 将仓库中的 `SKILL.md`、`skill-dependencies.json`、`references/`、`scripts/` 放入：
   - Windows：`C:\Users\<用户名>\.workbuddy\skills\what-to-eat-today\`
   - macOS/Linux：`~/.workbuddy/skills/what-to-eat-today/`
3. 重启或新开 WorkBuddy 会话，对助手说「帮我点麦当劳」即可触发。
4. （可选）脚本功能需要 Python 3.10+；缺失时自动降级为人工推理，不影响主流程。

## 使用示例

```
用户：帮我点麦当劳
助手：按默认先给你配一套：1 人、人均 30-40 元、到店自取——板烧鸡腿堡套餐 + 小食，
     预估 ¥35 左右（最终以门店实价和券后价为准）。想怎么吃？
     ①到店自取 ②得来速 ③麦乐送 ④团餐

用户：2，两个人，预算 80，不辣
助手：（选店 → 领券确认 → 真实试算 → 输出比价表）
【比价结果】XX 餐厅 · 麦乐送 · 试算时间 15:11
| 方案 | 原价 | 用券 | 券后实付 | 省 | 折扣 |
| ⭐方案A·板烧双人次 | ¥76.50 | 板烧立减券(满59减15) | ¥61.50 | ¥15.00 | 8折 |
| 方案B·麦辣双人次 | ¥68.00 | 无可用券 | ¥68.00 | — | — |
最划算：方案A，券后实付 ¥61.50

用户：就这套
助手：（硬确认四项后真实下单，引导扫码支付并跟踪订单状态）

用户：再点一次上次那个
助手：（还原最近一笔订单明细 → 按当前门店重新试算 → 硬确认 → 下单）
```

其他触发方式：「巨无霸多少钱」「中午吃什么」「找个得来速」「跟昨天一样」。竞品（肯德基等）、菜谱类、泛餐饮推荐不会进入点餐流程。
