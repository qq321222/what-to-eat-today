# 搭配策略

按人数/预算/口味生成候选菜单。结构模板 + 口味过滤，价格口径为菜单价预估，最终以 calculate-price 为准。

## 人均预算带（结构模板）

人均 = 总预算 ÷ 人数。多人时先按人均生成「每人份」骨架，再允许共享装合并（如大薯条共享）；团餐场景直接按本表套用。

| 人均 | 结构 |
|---|---|
| < 20 元 | 小食 |
| 20-30 元 | 汉堡 + 小食，或 汉堡 + 饮料 |
| 30-40 元 | 汉堡 + 薯条/小食 + 饮料 |
| 40-50 元 | 汉堡 + 薯条 + 小食 + 饮料 |
| > 50 元 | 丰富组合，优先不重复小食 |

时段修正：now-time-info 判定 10:30 前 → 早餐池优先。

## 口味标签映射

| 维度 | 标签值 | 典型商品 |
|---|---|---|
| 蛋白 | 牛肉 / 鸡肉 / 鱼 | 巨无霸、安格斯（牛）；麦辣、板烧、麦麦鸡（鸡）；麦香鱼（鱼） |
| 辣度 | 辣 / 不辣 | 麦辣、脆汁鸡含辣 |
| 饮料 | 无糖 / 常规 / 咖啡 | 按菜单饮料 tags 匹配 |
| 忌口 | 用户点名排除项 | 按名称关键词从池中剔除 |

匹配规则：用户说了偏好 → 只在符合标签的池内组；没说 → 全池组 2 套 + 主推 1 套经典款。

## 脚本执行

scripts/combo_builder.py 通过标准输入接收 JSON：

```json
{
  "meals": [{"code": "SKU01", "name": "板烧鸡腿堡", "priceCent": 2350, "category": "汉堡", "tags": ["鸡肉", "不辣"]}],
  "people": 2,
  "budgetCent": 8000,
  "preferences": {"meat": "", "spicy": "", "drink": "", "avoid": ["麦香鱼"]}
}
```

字段要求：meals 非空；people ≥ 1；budgetCent 为分（0 表示未给预算，按人均 3000-4000 默认带处理并注明）；preferences 各项可为空字符串，avoid 为名称关键词数组。脚本输出：

```json
{
  "combos": [
    {
      "name": "方案A·板烧双人次",
      "items": [{"productCode": "SKU01", "name": "板烧鸡腿堡", "quantity": 2, "priceCent": 2350}],
      "estTotalCent": 7600,
      "perPersonCent": 3800,
      "structureNote": "汉堡+小食+饮料（人均30-40元带）"
    }
  ],
  "notes": []
}
```

estTotalCent 为菜单价预估，仅供粗筛。呈现给用户时换算为元并声明「券后价下一步算」。

## 人工降级推理步骤

脚本失败或 Python 不可用时：

1. 按人均落预算带，写出结构骨架（如「汉堡+小食+饮料」）。
2. 按口味标签映射过滤菜单池（忌口先剔除）。
3. 每个结构位选 1-2 个候选商品（覆盖不同蛋白/辣度以形成 2-3 套差异）。
4. 菜单价手工加总核对不超预算×1.1，超出换更低价商品。
5. 输出前声明「估算价」；不阻塞主流程，最终仍以 calculate-price 为准。
